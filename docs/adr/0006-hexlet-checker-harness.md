# Conform to the Hexlet checker harness

The project is graded by the Hexlet auto-checker (`hexlet/project-action`), which imposes a run-time contract that the app must satisfy without changing the app's own architecture. As observed on 2026-10-20 against `hexlet/project-action@release`, the action pulls a harness image, copies the student checkout into `source/code`, and runs `docker compose` **from the harness image, not from the student repo**; the harness invokes `make setup`, then the `test` service whose exit code is the verdict. The checker also requires the `package.json` `name` to be `@hexlet/code`, and collects artifacts matching `tmp/artifacts/*/**` (glob one level down, ASCII paths). Consequences: we add a root `Makefile` with `setup`/`test`/`lint`/`build`, rename the root package to `@hexlet/code`, and write test reports and the asciinema demo under nested `tmp/artifacts/` paths. This does not supersede ADR-0005: we still ship one image; the harness compose is checker scaffolding around it, not an architectural decision. See ADR-0005. The cost is that the run contract is dictated externally and its exact criteria are not public, so these facts are a dated snapshot to revisit if the harness changes.
